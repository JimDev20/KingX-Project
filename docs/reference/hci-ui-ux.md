GESTURES
## Common Touch Gestures
TAP — Select or activate an element.
SWIPE — Scroll, navigate, or dismiss.
PINCH — Zoom in or out on content.
LONG PRESS — Reveal hidden options or context menus.
ROTATE — Adjust orientation or angle of objects.
## Discoverability & Risk
If a gesture is invisible, how does the user discover it? Hidden gestures create discoverability gaps. Users rely on visual cues, onboarding hints, or accidental discovery.
Risks: actions triggered unintentionally, no undo path, and exclusion of new users. Good design surfaces affordances.

**===== Page 27 =====**
1
# HUMAN MEMORY IS NOT A DATABASE
## RECALL
User must retrieve information from memory with no visual cues. High cognitive load. Error- prone. Example: Typing a command, remembering a shortcut, entering a URL from memory. Design risk: If the system doesn't show options, users forget or guess wrong.
## RECOGNITION
User selects from visible options — no memorization needed. Lower cognitive load. Faster and more accurate.
Example: Dropdown menus, autocomplete, icon toolbars, suggested replies.
Design principle: Show options. Don't make users remember what they cannot see.

# DESIGN TRADE-OFFS FOR DRIVERS
## Option A: Visual Controls
GAIN: Precise control, familiar layout, direct feedback, no errors from misrecognition. SACRIFICE: Eyes off road, high cognitive load, dangerous at speed, requires fine motor input. A RISK: Visual attention diverted from driving context.
## Option B: Voice Interaction
GAIN: Hands- free, eyes- free, safe for driving, natural language input, fast for short commands. SACRIFICE: Noisy environments break it, misrecognition errors, privacy concerns, limited precision. Option C — Minimal Physical Controls: Dedicated knobs/buttons. GAIN: Tactile, no- look input. SACRIFICE: Limited to preset functions, steep learning curve. "What do you gain? What do you sacrifice?"

# DESIGN TRADE-OFFS FOR DRIVERS
## Option A: Visual Controls
GAIN: Precise control, familiar layout, direct feedback, no errors from misrecognition. SACRIFICE: Eyes off road, high cognitive load, dangerous at speed, requires fine motor input. A RISK: Visual attention diverted from driving context.
## Option B: Voice Interaction
GAIN: Hands- free, eyes- free, safe for driving, natural language input, fast for short commands. SACRIFICE: Noisy environments break it, misrecognition errors, privacy concerns, limited precision. Option C — Minimal Physical Controls: Dedicated knobs/buttons. GAIN: Tactile, no- look input. SACRIFICE: Limited to preset functions, steep learning curve. "What do you gain? What do you sacrifice?"

# CASE STUDY #2 FOOD DELIVERY
Scenario A: In a Moving Car
User is a passenger ordering food while riding. Eyes may be on scenery. Motion may affect touch precision. Loud music or conversation present. Best interaction: VOICE + HAPTIC Why? Hands- free, eyes- free, quick confirmation.
Scenario B: Noisy Restaurant
User is seated but surrounded by noise. Voice commands fail due to ambient sound. Distracted by social context.
Best interaction: TOUCH + VISUAL
Why? Voice unreliable; visual menus and tap gestures work well.
